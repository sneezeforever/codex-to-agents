# 升级已有安装

旧版没有更新检测代码，无法收到新版看板的提醒。先按下面的步骤手动升级一次；之后可以从看板「插件更新」检查和安装更新。

## 1. 更新原来的 clone 目录

先等待正在执行的派工任务结束，在原来的 `codex-to-agents` 仓库目录运行：

```bash
git status --short --branch
git branch --show-current
```

确认当前在仓库默认分支（本仓库为 `main`）、跟踪正确的 `origin`，且没有待保留的源码改动，再运行：

```bash
git pull --ff-only
npm ci
```

如果提示存在本地改动或分支不能快进，先处理自己的改动或分支，再继续升级。无需重新 clone，也不要删除原来的插件数据目录或 SDD 文档目录。

## 2. 刷新本地安装

**沿用初次安装时的参数。** 特别是 `--home`、`--codex`、`--profile`、`--dsh-home`、`--directory`、`--provider`；使用过自定义值时，把原值带回相应命令，不要用默认值覆盖。

旧版没有保存连接传输。升级后如果没有显式选择，重装会采用默认 `stdio`；需要继续使用 HTTP 时，在第一次 `enable` 或 `plugin-install` 命令加上 `--transport http`。显式选择保存在数据目录，之后的重装、看板安装和「插件更新」都会沿用，不需要每次重复。非法或损坏的保存值会报错，不会静默切换。

- 使用 DSH：重新执行自己原来的 `node src/command.mjs enable ...` 命令，刷新 DSH 插件代码快照，随后重启 DSH。
- 使用 Hermes：插件运行代码直接来自原仓库；若只安装了派工工具、未安装看板，重新执行自己原来的 Hermes `enable` 命令，并按[安装教程](../README.md#3-安装-agents-看板)安装看板。
- 已安装看板：重新执行 `plugin-install`，让 Codex 载入新的工具与 Hook 配置。`enable` 只更新派工连接，不刷新已有看板；需要看板使用同一传输时必须运行 `plugin-install`。

原来使用默认数据目录、且 `codex` 在 PATH 中时，看板安装与后台重启命令如下。使用过 `--home` 或 `--codex` 时，请继续带上自己的原值：

```bash
node src/command.mjs plugin-install
node src/command.mjs backend restart
```

重启 Codex，关闭旧的看板页再重新打开。若提示 Hook 已更改，按 Codex 提示重新审核并信任；从旧版连接升级的已有会话也需重新加载。

找不到 `codex` 命令时，参考[指定 Codex CLI](../README.md#找不到-codex-命令怎么办)。

## 3. 确认升级成功

打开 Agents 看板，能看到「插件更新」，展开后可以查看当前提交并点击「检查更新」。

- 看板首次可见且连接成功时，每 24 小时最多自动检查一次；多个会话共享这条记录。
- 有新版时，折叠栏显示「发现可用更新」。点击展开查看详情，再由你点击「安装更新」。
- 手动「检查更新」可随时执行，不受自动检查间隔限制。
- 隐藏看板时暂停状态查询；检查或安装后的状态读取次数有限，没有常驻的更新轮询。
- 自动检查失败也计入当日尝试，可在网络恢复后手动检查。

更新入口只在 Codex 内嵌看板可用，独立浏览器的只读监控页不会检查或安装更新。自动检查不会自动安装；安装完成后仍按提示重新加载 Codex 或重启 DSH。
